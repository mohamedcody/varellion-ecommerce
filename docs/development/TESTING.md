# دليل واستراتيجية الاختبارات في مشروع VARELLION
# VARELLION Testing Strategy & Guide

> **الهدف:** توضيح كيفية كتابة وتشغيل الاختبارات الآلية لحماية قواعد الأعمال ومنع الانتكاسات (Regressions).

---

## 1. هرم الاختبارات في المشروع (Testing Pyramid)

1. **اختبارات الوحدة (Unit Tests):**
   - سريعة جداً وتختبر الدوال والـ Services والـ Mappers بمعزل عن قاعدة البيانات.
   - استخدام `Mockito` لعزل الاعتماديات الخارجية.
2. **اختبارات التكامل المنعزلة (Slice / Integration Tests):**
   - استخدام قاعدة بيانات `H2 In-Memory Database` لاختبار الـ Repositories والـ Queries المعقدة دون التأثير على قاعدة بيانات Supabase الحية.
   - اختبارات الأمان والتحقق من التوكنات (`JwtTokenProviderTest`).
3. **اختبارات الـ API (WebMvcTest):**
   - اختبار الـ Controllers والتأكد من إرجاع رموز الحالة الصحيحة (`200 OK`, `201 CREATED`, `400 BAD REQUEST`, `401 UNAUTHORIZED`, `404 NOT FOUND`).

---

## 2. أوامر تشغيل الاختبارات (Running Tests)

- **تشغيل جميع الاختبارات:**
  ```bash
  mvn test
  ```
- **تشغيل كلاس اختبار محدد:**
  ```bash
  mvn test -Dtest=JwtTokenProviderTest
  ```
- **تشغيل فحص البناء مع تخطي الاختبارات مؤقتاً (عند الضرورة القصوى):**
  ```bash
  mvn clean compile -DskipTests
  ```

---

## 3. القواعد الذهبية للاختبارات (Golden Rules)
1. **لا تختبر على داتابيز الإنتاج الحية:** لا تشغل اختبارات تنشئ أو تحذف بيانات في قاعدة بيانات Supabase الحية. استخدم بيئة الاختبار المنعزلة.
2. **لا تزور نتائج الاختبارات:** لا تقم بإلغاء اختبار أو إخفاء خطأ لتمرير عملية البناء؛ عالج المشكلة الجذرية دائماً.
